# ピンポンカット

卓球の試合動画から、ラリーの場面だけをつないだ動画を作るブラウザツール。サーバーなし・動画は端末から出ない・無料・登録不要。

## 使い方
1. ページを開いて動画を選ぶ
2. 「完全自動」にチェックがあれば、打球音からラリーを自動で見つけて書き出しまで進む
   - 違う所は手で直せる：ラリー中だけボタンを押す（押しっぱなし／タップ切替）、バーのドラッグ、一覧の ✕
   - 「見つける量」（少なめ／ふつう／多め）を変えるとすぐ判定し直す。「取り消す」で前の印に戻る
3. 「書き出す」→ 保存（スマホは「写真に保存・共有」）

## 書き出しのしくみ
1. **高速方式（通常）**：WebCodecs で必要なコマだけ読み取り→作り直し→MP4 に組み立て。再生しないので速い（60秒の動画で数秒）
   - 音は作り直さず元の音のかけらを並べる。区間の境目は音のかけらにそろえる → 音ズレなし
   - 映像の時刻は等間隔の格子に載せる（継ぎ目に短いコマを作らない）
   - 区間ごとに読み取り器を作り直す
   - 失敗時は診断文字列（どの段階・何本目・形式）をコンソールとエラー文に出す
2. **控え**：高速方式が使えないブラウザでは、再生しながら MediaRecorder で録画（実時間ぶんかかる）

## 自動判定のしくみ（`detect.js`）
映像と音を組み合わせる。音だけでは、台がたくさんある会場でほかの台や足音と区別できない。映像だけでは、球が小さくぶれていて追えない（実際の試合動画で、ラリー中のコマの 3% しか拾えなかった）。そこで役割を分ける。

1. **始まり＝映像**：サーブの前は 2 人とも構えて止まる。縮めた映像（160×90・1 秒に 10 コマ）で動いた画素の割合を出し、「0.5 秒以上止まる → 動き出す」をラリーの始まりにする
2. **終わり＝音**：始まりから次に止まるまでの区間の中だけで打球音を探し、最後の打球音を終わりにする（打球音が 1.8 秒とぎれたらそこまで）
   - 打球音＝高い音が主体の短く鋭い音。足音は低い音も一緒に鳴るので外れる
3. 動き出して 5 秒以内に打球音が無い区間は捨てる（止まって動いただけ）

基準の数値は `detect.js` の `AV_PRESETS` とその下の定数にまとめてある。映像を読めない端末では、音だけの判定（`findRallies`）に切り替わり、その旨を画面に出す。

- **確認できているのは、大会会場で撮った 41 秒の試合動画 1 本だけ**（5 本中 5 本を検出。始まりは 0.5〜0.8 秒早め、終わりは最後の打球から 0.3 秒後。1 本だけ終わりが約 1.7 秒長い）。基準はこの 1 本に合わせたもの
- その動画は切り抜き済みだったので、「止まる」はすべてサーブの構えだった。切り抜く前の動画にある別の「止まる」（立ち話・タオル休憩など）でどうなるかは未確認
- 苦手なはずのもの：手持ちで揺れる動画、ラリーの途中から始まる動画、構えずにすぐサーブする場面、音のない動画
- 所要時間：Chromium（ソフトウェア復号・1080p）で 41 秒の動画に約 20 秒（書き出し込み）

音の読み取りは 3 段がまえ：① WebCodecs で少しずつ読む（Chrome など）→ ② AAC を約 20 秒ずつの小さなファイル（ADTS）に分けてブラウザ標準の機能で読む（WebCodecs で音を読めない Safari など）→ ③ 丸ごと読む（600MB まで）。②は Node 上で ffmpeg に読ませて①と同じ結果になることを確認済み。Safari の実機では未確認。

**判定の記録**：自動判定のあと「判定の記録を保存」で `pinponcut-kiroku.json` ができる。中身は 5 ミリ秒ごとの音の大きさ（3 つの帯）・1/10 秒ごとの動きの量・自動で見つけた区間・いまの印。印を手で直してから保存すれば、それが正解になり、基準の見直しに使える。動画や音そのものは入らない。

## 公開前に設定するもの（`index.html` の先頭）
- `FEEDBACK_URL`：感想フォーム（Googleフォームなど）の URL。空なら非表示
- `GOATCOUNTER_CODE`：GoatCounter のコード名。空なら解析なし。記録する出来事：`1-動画を選んだ` `2-印をつけた` `3-書き出しを押した` `4-書き出せた` `x-高速方式が使えなかった` `x-録画も失敗` `x-書き出しが空だった` `a-自動で見つけた` `x-自動で見つからなかった` `x-自動判定できなかった` `x-映像を読めず音だけで判定`

## 確かめ方
Playwright の Chromium は H.264 を読めないので、VP9 入りの MP4 でテストする。`export.js` は ES モジュールなので `file://` ではなく `python3 -m http.server` などで開く。
```
ffmpeg -f lavfi -i testsrc2=size=1280x720:rate=30 -f lavfi -i sine=frequency=440:sample_rate=48000 \
  -t 20 -c:v libvpx-vp9 -b:v 1M -deadline realtime -cpu-used 8 -c:a libopus -shortest test.mp4
```
